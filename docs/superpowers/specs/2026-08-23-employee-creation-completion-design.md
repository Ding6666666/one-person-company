# 员工创建完成体验设计

**日期：** 2026-08-23  
**范围：** `apps/dsh-company-plugin` 员工创建向导、通用弹窗和员工响应解析

## 目标

让员工创建流程具有明确、可恢复且一致的完成体验：昵称可以留空，创建成功后弹窗关闭并立即显示员工卡片，当前本地服务返回的既有员工响应不会再被误判为 `invalid_company_response`，创建界面始终提供可见的关闭入口。

## 交互规则

1. “昵称”标记为选填，不参与档案步骤的必填校验。
2. 用户没有填写昵称时，提交数据中的 `display_name` 使用去除首尾空白后的工作类型。
3. 昵称输入框保持为空，不把回退名称写回表单；确认页使用最终显示名称预览。
4. 员工创建接口返回成功后，控制器将员工加入当前工作区列表，随后创建员工弹窗关闭。
5. 创建员工弹窗右上角提供带可访问名称的关闭按钮；底部取消按钮和 Escape 关闭继续保留。
6. 请求失败时弹窗保持打开，便于用户调整或重试。

## 响应兼容

当前运行中的本地 Company Service 存在两个已实际观察到的响应版本：较早版本的 `revision` 缺少角色档案字段，较新版本仍可能缺少 `system_prompt`。前端员工响应解析器对这些缺失字段采用领域现有默认值：

- `system_prompt`: `""`
- `role_template_key`: `"custom"`
- `work_type`: `"自定义工作"`
- `avatar_key`: `"custom"`
- `skill_refs` / `tool_refs`: `[]`

核心标识、绑定、授权和状态字段仍然严格校验。这样只兼容项目当前确实产生的历史响应，不放宽无关契约。

## 视觉与可访问性

关闭按钮放在弹窗标题行右上角，使用现有按钮和色彩体系，具备清晰的 hover/focus 状态。按钮文本通过翻译函数传入，图形本身不作为唯一可访问名称。标题与关闭按钮组成弹窗头部，不改变既有内容布局和焦点陷阱。

## 验收标准

- 昵称为空时可以完成五步向导，请求中的显示名称等于工作类型。
- 昵称存在时继续优先使用昵称。
- 创建成功后弹窗消失，新员工卡片可见，页面不显示 `invalid_company_response`。
- 创建失败后弹窗不关闭。
- 鼠标点击关闭按钮、底部取消按钮或按 Escape 均可关闭创建界面。
- 新旧两种已观察到的员工响应均可解析；缺少核心字段的无效响应仍被拒绝。
